# 通用权衡框架

第 7 步使用。脱胎于 Microsoft amplifier-bundle-systems-design 的 8 维权衡矩阵（MIT 许可证），泛化到非技术决策。核心问题不变：

> **这个方案优化了什么，牺牲了什么？** 答不出，就是还没想透。

## 目录

1. 八个维度
2. 比较矩阵模板

## 1. 八个维度

| 维度 | 关键问题 | 警惕 |
|------|----------|------|
| **效果** | 它真正解决目标问题吗？解决到什么程度？ | 把"做了事"当"解决了问题"；指标改善 ≠ 目标达成 |
| **成本** | 金钱、时间、注意力、机会成本，现在和放大后各是多少？ | 现在线性、日后超线性的成本曲线（规模上去后爆炸） |
| **复杂度** | 需要同时在脑子里装几个概念？几个并行的流程/承诺？ | 操作复杂度和表面复杂度会背离；"看起来简单"不等于运营起来简单 |
| **风险与鲁棒性** | 最坏情况多坏？部分失败时还剩什么？ | 平均情况好、尾部崩溃的方案；单点依赖 |
| **可逆性** | 后悔了撤回来有多难？ | 不可逆决策要证据最足时才做；数据/承诺/习惯最难回滚，执行细节最容易 |
| **可扩展性** | 规模（用量、时间、人数）上去后，什么先撑不住？ | 扩展性最差的那一环就是瓶颈 |
| **时机** | 为什么是现在？窗口期真实存在吗？ | 把"焦虑"当"窗口期"；也警惕用"再等等"掩盖不敢决策 |
| **契合度** | 与执行者的真实能力、价值观、资源结构匹配吗？ | 理论上正确、执行者操作不了的方案等于失败方案 |

非技术决策可替换措辞但不可随意增删维度；少于 2 个候选方案说明没放开假设，多于 5 个先收窄。

| 维度 | 方案 A | 方案 B | 方案 C |

| 成本 | | | |
| 复杂度 | | | |
| 风险与鲁棒性 | | | |
| 可逆性 | | | |
| 可扩展性 | | | |
| 时机 | | | |
| 契合度 | | | |
| **优化了** | [一句话] | | |
| **牺牲了** | [一句话] | | |

评分用"好 / 尚可 / 差"加一句具体依据，不用数字打分——数字制造虚假精确。

## 3. 使用规则

1. **先填格子，再谈结论。** 空格 = 没检查过的风险。
2. **找主导权衡。** 拉开差距的通常只有 1–2 个维度，真正的决策就在那儿，不要在八维上平均用力。
3. **必须写出"牺牲了"。** 没有牺牲的方案描述是不完整的方案。
4. 快速模式：表格可省，但"优化了/牺牲了"两行不能省。

## 4. 催化问题

收尾必问：

> **"什么必须为真，这个选择才会是错的？"**

这个问题同时完成两件事：暴露方案赖以成立的隐藏假设；给出决策失败时应该监测的信号（看到了什么就该回头）。
