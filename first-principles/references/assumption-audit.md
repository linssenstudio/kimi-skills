# 陈述审计：事实 / 假设 / 观点 / 约束

第 1 步（四分标注）的操作手册。目标：把撑起当前思路的陈述逐条归类，找出其中哪些是未经检验的沙子。

## 目录

1. 四类陈述的判别标准
2. 高频假设伪装（看起来像事实的假设）
3. 惯例识别线索
4. 前提挑战问题清单
5. 裁决规则

## 1. 四类陈述的判别标准

| 类别 | 判定标准 | 例子 |
|------|----------|------|
| **事实** | 可被独立验证，且已被验证；或可当场验证（数学、物理、已签署的合同、已发生的事件） | "上月复购率是 18%"、"合同 12 月到期"、"门店租金每月 3 万" |
| **假设** | 被当作事实使用，但缺少验证；预测类、归因类、"没否认即同意"类陈述几乎都是假设 | "用户流失是因为价格"、"年轻人不喜欢打电话"、"客户看了方案没回复就是嫌贵" |
| **观点** | 明确属于某人的判断、偏好、品味；可以尊重但不能当事实推理 | "老板觉得应该先做品牌"、"我认为简约风更好" |
| **约束** | 当前不可改变的条件；改变它要么不可能、要么代价大到本轮不考虑 | "预算 50 万"、"必须在 6 月前上线"、"技术上只能用现有系统" |

判定口诀：**"谁说的、凭什么、能复查吗"** —— 能复查且已复查的是事实；不能复查却被当事实用的是假设；明说是谁觉得的是观点；改不了的是约束。

## 2. 高频假设伪装

以下句式出现时要亮起红灯：

- 归因无证据："是因为……"、"问题在于……"（后接未经检验的原因）
- 全称判断："用户都……"、"市场永远……"、"从来没人……"
- 沉默推断："他没反对，说明他同意"、"没人投诉，说明没问题"
- 类比当证明："别人这么做成功了，所以我们也会"（别人的约束和你不同）
- 解决方案当需求："我们需要一个公众号 / App / 中台"（用户真正的需求藏在后面）
- 数字当事实："行业平均转化率 3%，所以我们也会有 3%"（行业平均 ≠ 你的处境）
- 沉没包装："已经投了这么多钱，必须继续做"（已投入不是继续做有效的理由）

## 3. 惯例识别线索

一个做法是"惯例"而非"必然"的信号：

- 解释它时只能说"一直都是这么做的"、"同行都这么做"，说不出它当前解决的具体问题。
- 它诞生的时代条件已经变化（技术、渠道、成本、法规、用户习惯）。
- 它的存在会让提问者显得外行——惯例往往靠"不好意思问"存活。
- 剔除它之后，目标仍然可以被别的路径达成。

注意反向陷阱：不要因为"这是惯例"就否定它。惯例可能凝结着别人付过学费的经验。正确动作是让它**重新赢一次**：说出它解决什么问题、这个问题现在是否仍成立、有没有更便宜的解法。

## 4. 前提挑战问题清单

对每条假设/惯例，按顺序问（一轮即可，每问必有裁决）：

1. **证据**：支持它的证据是什么？证据有多硬（一手数据 / 二手报告 / 传言 / 无）？
2. **反例**：存在它不成立的场景吗？那个场景离我们有多近？
3. **反演**：如果它的反面为真，结论会不会完全改变？（会 → 这是关键假设，必须验证；不会 → 降级为次要假设）
4. **必要性**：它是目标本身，还是达成目标的某一种方式？
5. **来源**：它是谁的观点？那个人有什么立场或盲区？

## 5. 裁决规则

每条假设挑战后必须落入三个去向之一：

- **保留为约束**——经得起证据和反演检验，或确属不可改变条件。
- **标记为待验证假设**——进第 8 步配一个最低成本验证方法。
- **淘汰**——证据不足且反演后不影响结论，或纯粹是伪装成事实的观点。

禁止悬置：不允许分析结束时仍有"未裁决"的假设。
