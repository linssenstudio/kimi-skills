# 失败场景模拟方法

第 5 步使用。标准模式对 P0/P1 级风险做模拟；深度模式对全部重要风险构建模拟矩阵。

## 目录

1. 预验尸（Premortem）
2. 红队攻击
3. 极端条件测试
4. 情景推演
5. 深度模式：失败矩阵

## 1. 预验尸（Premortem）——首选方法

假设对象已经失败（项目黄了 / 决策后悔了 / 作品翻车了），现在是事后复盘现场。

操作：
1. 设定时间："[6 个月后]，这件事失败了。"
2. 不讨论"会不会失败"，直接问"**最可能的死因是什么**"——迫使大脑绕过防御性乐观。
3. 每个死因按"发生概率 × 损失"粗排，取前 3–5 个进入分级流程。
4. 对最高死因问一句："现在的方案里，有什么专门防它的？" 没有 → 直接进 P0/P1。

预验尸的价值在于它把"唱反调"变成了"团队任务"，产出的死因往往比正向风险清单更具体。

## 2. 红队攻击

站在**希望对象失败的人**的立场找攻击面：

- 商业：竞争对手会怎么反击（降价、挖人、抄模式、封渠道）？哪个反击对象最扛不住？
- 内容：反对者会怎么断章取义？截取哪一句话能让作者最难受？那句经得起单独出现吗？
- 制度：被管理者会怎么钻空子？钻空子是否比遵守更划算（是 → 制度必败）？
- 个人决策：劝你放弃的朋友会说什么？其中哪句是真的？

## 3. 极端条件测试

把关键变量推到边界，看方案是否仍有形状：

- 资源砍半：预算/时间砍 50%，方案还成立吗？（不成立 → 方案脆弱，需要韧性设计）
- 关键人消失：最重要的那个人退出/生病/离职，还能运转吗？
- 需求翻倍：用户量/工作量 ×2，什么先断？
- 环境反转：利率/政策/平台规则/健康状态向相反方向变化，损失可承受吗？

## 4. 情景推演

对一个具体的高危风险，按四格展开：

```
触发条件：[什么具体事件/数据标志着风险开始兑现]
发展路径：[第一步 → 第二步 → 第三步，每步谁做什么]
损失边界：[最坏亏多少：钱/时间/声誉/关系，量化到数量级]
可挽回性：[在哪个时间点之前还能回头？回头成本？]
```

推演产出直接填入质疑五要素的"影响"和"验证方法"两格：触发条件往往就是该设置的监测信号。

## 5. 深度模式：失败矩阵

| 风险 | 触发条件 | 概率 | 损失 | 级别 | 监测信号 | 预案存在？ |
|------|----------|------|------|------|----------|-----------|
| [风险1] | | 高/中/低 | 量级 | P? | | 有/无 |

规则：预案不存在且级别 ≥P1 的，必须在行动清单中出现"补预案"一项。
