# 严重程度分级与报告格式

第 7–8 步使用。

## 目录

1. 分级定义
2. 质疑五要素
3. 报告模板
4. 排序规则

## 1. 分级定义

| 级别 | 定义 | 判断问句 |
|------|------|----------|
| **P0 阻断级** | 不解决就不应继续：目标落空、重大损失、不可逆伤害的现实风险 | "如果这个问题是真的且不改，对象还有意义吗？" —— 否 → P0 |
| **P1 重要级** | 显著降低成功率或显著增加代价；不解决也能跑，但跑不远 | "这个问题会让对象的预期价值打几折？" —— 明显打折 → P1 |
| **P2 改进级** | 质量、效率、体验提升；不解决不影响存活 | "解决了会更好，不解决会怎样？" —— 不怎样 → P2 |
| **P3 提示级** | 值得留意的信号、趋势、观察 | "我现在能为此做什么吗？" —— 不能 → P3 |

校准规则：

- **可逆性调制**：不可逆决策（辞职、买房、签合同、上线）中同等问题升一级；可逆小实验（发一篇内容、试一周新流程）中降一级。
- **概率 × 损失**：级别 = 损失程度 × 发生概率的综合判断，不是只看损失上限。低概率末日 ≠ P0；高概率重伤 = P0。
- **证据强度调制**：有明确证据支撑的问题升一级，纯推测的质疑降一级，并在依据里写明证据状态。

## 2. 质疑五要素（P0/P1 必填）

```
质疑：[一句话说清问题]
依据：[证据或论证——为什么这是个真问题。证据不足时写"推测，待验证"]
影响：[发生后最具体的后果，不接受"可能有风险"这种空话]
严重程度：[P0/P1/P2/P3 + 一句理由]
验证方法：[最便宜的确认真伪的方式]
改善建议：[方向性建议，一句话；不是替用户重写方案]
```

P2/P3 可压缩为一句话，但必须有依据。

## 3. 报告模板

```markdown
## 总体判断
[一句话：对象当前处于什么状态——可继续 / 修改后可继续 / 不建议继续]

## 做对了什么
[2–4 条。只报忧的审查不可信；此节也是"哪些部分不要再动"的保护清单。]

## P0 阻断级问题
（五要素格式；没有就写"无"）

## P1 重要级问题
（五要素格式）

## P2 改进建议
（压缩格式）

## P3 提示
（一句话观察）

## 行动清单
[按优先级排序的最小修改集：先改哪 1–3 项，改到什么程度算过关]
```

快速模式压缩版：

```markdown
## 总体判断
## Top 3 问题（含五要素）
## 做对了什么
## 下一步
```

## 4. 排序规则

- P0 全部排在 P1 之前；同级内按"验证成本低的优先"（先花小钱排雷）。
- 行动清单最多 5 项，超过说明分级过松——回去重新分级。
- 报告结尾的判断必须与分级一致：有 P0 未解决却给"可继续"，必须解释理由。
